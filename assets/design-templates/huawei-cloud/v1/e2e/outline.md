# E2E场景测试设计模板

- E2E场景测试设计模板
  - 背景
    - 项目信息
      - 工具、自动化有哪些新诉求？
      - 对于环境有哪些特殊要求？
      - 需要提前储备哪些技能/知识？
      - 和周边微服务有哪些配合诉求？
    - 需求背景
      - 【需求编号】
        - FE2022110300015
          - 需求链接：https://xxxxx.com
      - 【需求背景】
        - 需求功能：本FE涉及XXX功能
          需求范围：转测涉及周边领域，XXX，XXX
          总体要求：
          1、在保证转测版本时间点的基础上，各部门开发节奏可灵活安排
          2、与云服务相关场景测试需要打桩
          3、功能要考虑增加特性开关，保证上线的能力跟云服务的版本解耦
          4、XXXXXX
          需求描述：
          1、XXXX
          2、XXXX
          3、XXXX
      - 【文档路径】
        - 【环境信息】：https://xxxxx.com
        - 【架构设计图】：https://xxxxx.com
        - 【方案/规格路径&附件】
          - .../2022设计文档/设计规格说明书.docx
          - .../2022设计文档/数据分析需求设计说明书.docx
          - ...
        - 【UCD高低保真地址&附件】：https://xxxxx.com
        - 【业务地图URL路径】：https://xxxxx.com
  - 测试分析
    - 【测试策略分析】
      - 【因子分析】
        - 【站点】
          - 国际站
            - 该功能仅在中国站上线
          - 中国站
          - 跨站点
            - 该功能仅在中国站上线
        - 【国界】
        - 【客户】
          - 直销客户
          - 伙伴子客户
          - 企业客户
          - 引流客户
        - 【产品】
          - XXX 商用
        - 【入口】
          - 云服务控制台
          - 移动端
        - ...
      - 【业务场景分析】
        - 可以基于【因子分析】中分析到的因子，进行关系整理，并作为下面【场景X】的节点存在
        - 订购流程
          - 订购
            - 客户类型
              - 直销客户，购买"XX软件License"支付成功
              - 代售客户，购买"XX软件License"产品支付成功
              - 内部客户，不支持购买"XX软件License"
            - 订单操作
              - 直销客户，生成多个"XX软件License"的待支付订单后，合并支付成功
              - 直销客户，"XX软件License"的待支付订单与其他非License类的订单，合并支付成功
          - 履行
        - 退订
          - 自助退订
          - 自动退订
          - 特殊退订
        - 开票
          - 按订单开票
          - 自定开票
    - 【新区】
      - 【深巷场景】
        - 极限测试
          - 并发场景
            - 同一页面对同一操作发起高频操作
            - 多个窗口页面对同一操作触发
              - 打开多个窗口，对同一个"XX软件License"订单进行支付
            - 不同客户端发起同一流程的处理
              - 手机端和web端都进行订单支付，验证支付状态
            - 多个流程触发对同一数据的处理（如：用户处理时，后台定时任务同步在处理）
          - 异常场景
            - 涉及国界时，需要给用户明确友好的提示
              - 4XX错误（请求问题），系统需要进行处理后提示用户
              - 5XX错误（南向服务端问题），异步流程需要有重试类型的保护机制，同步流程需要给客户友好提示
        - 破坏测试
          - 模拟"XX软件License"订单支付时，突发网络问题，验证是否支付成功，是否扣款成功
      - 【深夜场景】
        - 定时任务
          - 测试X个月之前的订单会被每天午夜12点定时任务自动归档，归档成功
        - 定时任务运行时，同时测试功能
          - 测试定时任务在运行时，同时创建新的"XX软件License"订单
        - 长期持续测试
          - 使用自动化手段，持续创建"XX软件License"订单、持续支付订单12小时
      - 【超模场景】
        - 多语言
          - 切换网站显示语言，不同语言下，不能出现换行、按钮被遮挡等界面问题
        - 易用性
          - 订单支付时，有价格计算器可快速计算价格和折扣
        - 界面布局
        - 提示合理性
    - 【旧区】
      - 恶邻场景
        - 根据关键字搜索现网问题，进行漏测分析，补充用例
          - 发票预览页面预览显示错误
          - 手机与PC 端同时支持时展示错误
      - 博物馆场景分析
        - 根据历史上已有特性场景，因为本次需求而有引入问题的风险，需要进行基本功能的保证（兼容性测试）
          - 验证直销客户操作非Liense类商品可以下订单并且支付成功
        - 本次测试需要关注但非重点测试的内容
    - 【行业分析】
      - 【产品架构】
      - 【功能分析】
        - 基于产品定位、目标用户、运营模式去分析竞品增加/存在一个功能它的目的是什么
        - 有哪些功能？
        - 功能交互逻辑分析
        - 共有功能可只分析差异，某一类功能是某一竞品独有，则可能是该竞品差异化的点（可重点说明）
      - 【交互设计】
        - 从功能入口开始分析，而不要从功能主体开始
        - 以目标操作任务为主干，避免被分支功能分散
      - 【视觉表现】
        - 页面的色调，布局结构
      - 【他山之石】
        - 竞品中亮眼的设计或者功能
    - ...
  - 测试覆盖
    - 输出所有“测试分析”环节中的分析过的，且适用于此需求的场景
    - 【场景1】
      - 【子场景1】
      - 【子场景2】
      - 【子场景3】
    - 【场景2】
      - 【子场景1】
      - 【子场景2】
      - 【子场景3】
    - ....
      - 【子场景1】
      - 【子场景2】
      - 【子场景3】
      - ...
  - 障碍
  - 风险
