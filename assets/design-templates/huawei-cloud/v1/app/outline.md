# App测试策略模板

- App测试策略模板
  - 背景
    - 【需求编号】
    - 【需求背景】
      - 需求场景分析
        - 需求本身要达到什么目的？
        - 有哪些需求使用场景？
    - 【文档路径】
  - App功能测试
    - 业务流程及内部逻辑
    - 用户操作及界面分析
      - 最终用户如何操作界面？
    - 接口
      - 涉及到的接口有哪些？
    - 数据操作
      - 涉及读取SIM卡、手机号信息的地方，是否考虑了双卡、更换SIM卡的场景
      - 涉及数据存储的功能，是否覆盖了检查数据存储正确性检查
      - 涉及数据读取的功能，是否覆盖了数据读取正确性的检查
      - 是否覆盖了数据操作异常的场景
    - 特性交互
      - 是否存在数据在不同特性间变更
      - 是否存在多个特性对同一数据并发处理
    - 用户信息/资产
      - 涉及到的用户信息/资产在登录后如何展示？
      - 被踢/注销后涉及到的用户信息/资产如何展示？
      - 帐号切换后涉及到的用户信息/资产如何展示？
  - 兼容性测试
    - 分辨率兼容性
      - Android
      - iOS
    - 云测试平台
      - 版本基本功能具备提交MQC进行兼容性测试
        - crash出现超过1次的提单跟踪，ANR超过10次的提单跟踪
    - OS版本
      - Android
      - iOS
    - 多终端
      - 涉及哪些需要各端保持一致的特性
      - 涉及哪些需要导致不同终端出现冲突的场景？
      - 涉及哪些需要不同端互通的场景？
  - 界面元素测试
    - 提示语
      - 提示语归一化
        - 整理全量提示语到管理表格中，使用统一key
        - 各端采用复制的方式替换对应场景下提示语
        - 各端替换对应场景下的key，并使用自动生成的资源文件
      - 策略
        - 对于国际版：对客户端使用的资源文件进行拼写和语法检查
        - 对于归一化落地后的策略
          - 替换统一key后，需要针对场景逐个核对
          - 采用自动生成的资源文件后，需要检查下展示的机制
    - 低保真
      - 根据最新低保真进行比对，APP交互是否实现有误
    - 界面元素
      - 根据最新高保真进行比对，APP界面是否实现有误
    - 高保真
      - 策略
        - 根据变更涉及到的高保真，由UCD专人检视
  - 安全性
    - 敏感信息
    - 原始通信内容
    - 安全传输通道
    - 是否涉及处理敏感信息/用户通信内容
    - 是否涉及加密算法
    - 是否涉及webview
      - 涉及到哪些URL
  - 稳定性测试
    - 云测试平台
      - 版本基本功能具备后提交MQC进行稳定性测试
    - 进行monkey脚本测试
      - 选择各个主页面作为初始页面
        - 修改脚本，操作不间断8小时后查看无崩溃，anr
  - 可靠性测试
    - 服务器报文异常
      - 视项目进度情况开展
      - 考虑各个端在异常时是否崩溃
    - 网络可靠性
      - 网络切换
        - WIFI-WIFI
        - WIFI-数据网络
        - 数据网络-WIFI
        - 无网-有网
    - 突发事件
      - 各个主页面（如订购）
        - 来电、短信
        - 锁屏/解锁
        - 系统提醒：闹钟、日程、地点提醒等
        - 前后台切换
    - 超时机制
      - 在各个主页面进行超时操作
        - 首次获取数据
        - 非首次（获取过数据杀掉进程进入）
        - 非首次（获取过数据，未杀进程进入）
        - 网络恢复
    - 网络QOS注入
      - 丢包:20%/时延:2000ms/抖动:25%
      - 使用ATC，以丢包:20%/时延:2000ms/抖动:25%标准处理
    - 关键资源异常
      - 内存不足
      - 删除部分文件、目录
        - 存储图片、配置文件
  - 专项性能测试
    - 页面切换/滑动流畅性
    - 时延
      - 安装/升级时间
      - 启动
        - 首次
        - 非首次
      - 首页加载
      - 二级页面加载
    - 电量
      - Android
        - 关闭其他应用，然后使用30分钟后查看设置中的当前应用电量
      - iOS
        - 关闭其他应用，使用30分钟后查看消耗电量
    - 流量 
      - Android
        - 以华为手机为例，运用4G，使用30分钟在流量管理里查看当前应用消耗流量
      - iOS
        - 运用4G，使用30分钟在蜂窝移动网络中查看当前应用消耗流量
    - 内存/CPU占用
      - AppServer专项优化
        - 性能测试方法：不断增加并发用户，当cpu达到70%后稳定20分钟后还是在70%采集当前并发用户、响应时间、吞吐量；反之增加并发用户，如果期间报错需要分析
