# 接口测试设计模板

- 接口测试设计模板
  - 风险
  - 障碍
  - 背景
    - 项目信息
      - 工具、自动化有哪些新诉求？
      - 对于环境有哪些特殊要求？
      - 需要提前储备哪些技能/知识？
      - 和周边微服务有哪些配合诉求？
  - 测试覆盖
    - 接口参数校验
      - 哪些参数需要做边界值测试？
        - 枚举值之外
        - 取值区间边界
          - 上点测试
            - 最大、最小
          - 离点测试
        - 长度越界测试
          - 最大值
          - 最大值+1
          - 最小值
          - 最小值-1
      - 哪些参数需要做可选必选测试？
        - 必选字段
          - 必选字段不携带
            - 字段1
            - 字段2
            - ...
          - 字段有值但值为空
            - String，取值为空串""和NULL
            - Int，取值为NULL
            - 数组，空数组即[]
        - 可选字段
          - 可选字段携带
          - 可选字段不携带
          - 可选字段携带，但值为空
            - String，取值为空串""和NULL
            - Int，取值为NULL
            - 数组，空数组即[]
        - 有条件可选字段
          - 满足可选条件，字段不携带
          - 满足可选条件，字段有值，值为空
            - String，取值为空串""和NULL
            - Int，取值为NULL
            - 数组，空数组即[]
        - 有条件必选字段
          - 满足必选条件，字段不携带
          - 满足必选条件，字段有值，值为空
            - String，取值为空串""和NULL
            - Int，取值为NULL
            - 数组，空数组即[]
      - 哪些参数需要做数据类型测试？
        - Number
          - 取值为String时的处理
          - 需要覆盖哪些负值？
        - String
          - 取值为Number类型的处理
          - 要支持哪些字符类型或者组合？
            - 数字
            - 字母
            - 特殊字符
          - 不支持的哪些字符类型或者组合？
        - Boolean
          - 非 boolean
      - 哪些字段需要做特殊字符的安全校验测试？
        - 哪些字段需要测试拦截的特殊字符？
        - 哪些字段需要对转义特殊字符进行处理？
      - 接口什么调用方式？
        - 接口URI是什么？
          - /XXXXX/XXXXX/YYYYYY
        - 调用方式是什么？
          - GET、PUT、POST、DELETE
    - 接口功能覆盖
      - 业务流程
        - token处理的约束
          - 涉及用户业务数据的查询/操作接口，系统token调用时需要做白名单鉴权
        - 接口处理流程新增或者修改了哪些步骤/场景？
          - 每个步骤/场景会受哪些因子影响？
            - 北向接口调用的输入
            - 数据库表的字段
            - 南向接口调用返回字段
            - 系统参数
              - 系统参数是否可以统一配置？
          - 每个影响因子可能会有哪些取值？
            - 需要覆盖哪些？
            - 字段内容支持哪些字符类型或者组合？
              - 数字
              - 字母
              - 特殊字符
          - 因子和因子之间有哪些关联组合关系？
            - 需要覆盖哪些？
          - 因子和因子之间有哪些互斥关系？
            - 需要覆盖哪些？
        - 每个业务流程会产生哪些数据？
          - 会有哪些数据库对象操作？
            - 哪些表会新增或者修改记录？
            - 表的哪些字段需要特别关注？
          - 接口响应返回哪些数据？
            - 哪些响应消息的关键字段需要重点检查？
            - 接口返回的关键字段，可能会有哪些取值？
              - 需要覆盖哪些取值？
              - 取值的单位是否要求？
                - 时间
                - 金钱
            - 接口响应消息一致性需要做哪些测试？
              - 参数字段名称、大小写是否符合要求?
              - 字段取值的类型和表达格式，是否合接口定义要求？
                - 字段取值的类型
                  - int？
                  - string？
                  - 数组？
                  - 对象？
                - 字段取值的格式要求
                  - 时间格式
                  - 日期格式
                  - XXX格式
              - 可选参数、必选参数
                - 可选字段无返回值时，是否返回空标签？
                - 可选字段有返回值，可选字段是否返回？
                - 必选字段是否全部返回？
              - 编码格式需要符合协议要求
                - 返回字段中是否可能有需要转义的特殊字符？
                - 返回字段中，是否可能含有中文？
                  - 采用什么字符集返回？
              - 返回字段的取值需要关注哪些特殊要求？
          - 流程处理中会调用哪些南向接口？
            - 调用哪些南向接口？南向接口包括kafka的调用
            - 调用的南向接口有哪些关键字段？
            - 关键字段需要覆盖哪些取值？
            - 调用南向接口的协议一致性测试
              - 消息结构体符合定义
              - 字段名称、大小写符合要求
              - 字段取值和格式，符合解耦定义
              - 可选参数、必选参数符合要求
              - 编码格式需要符合协议要求
                - 特殊字符需要转义
                - 中文编码需要符合字符集要求
              - 对于南向请求中token的正确使用
          - 会产生哪些文件？
            - 是否会产生文件？
            - 文件名字和存储位置是否有要求？
              - 文件名称是否允许重复？
              - 文件存储子文件夹层级是否会超长？
              - 一个文件夹下的文件个数是否会超多？
            - 文件有哪些关键字段？
            - 需要覆盖哪些关键字段的取值？
        - 该接口跟其他接口有无数据交互？
          - 该接口返回的数据会对本域其他哪些接口有影响？
            - 需要其他接口关注什么？
          - 该接口对数据库对象操作会对哪些接口有影响？
            - 需要其他接口关注什么？
      - 计费模式
        - 一次性
        - 包年包月
        - 按需
        - 按需套餐包
      - 返回码测试
        - 有哪些返回码是需要独立测试的？
    - 接口性能覆盖
      - 该接口是否为批量接口？
        - 批量接口需要验证大数据量
          - 数据量？
        - 批量调用有无最大限制？
          - 边界测试
      - 该接口是否为分页返回？
        - 每页的最大返回数是多大？
          - 边界测试
        - 分页内容是否需要排序？
          - 排序规则是什么
      - 该接口是否为是现网频繁使用的接口？
        - 该接口是否对涉及到大表的增删改查？
    - 接口可靠性覆盖
      - 本接口是否支持幂等？
        - 是否需要覆盖幂等测试？
      - 数据库异常时，接口的处理？
        - 数据库停掉，接口的处理？
          - 数据库停止，业务立即失败，进程不挂起
          - 数据恢复后，进程自动重连数据库
        - 数据库表锁时，接口的处理？
          - 有锁等待超时时间，超时后释放数据库连接，继续处理业务
      - 是否涉及南向接口调用？
        - 南向接口调用超时不响应时，接口的处理？
          - 是否支持重试？
          - 重试是否有重试次数限制？
        - 南向接口服务停掉时，接口的处理？
          - 是否支持重试？
          - 重试是否有重试次数限制？
        - 南向接口返回消息结构体不对，接口的处理？
        - 南向接口调用延时返回，接口的并发处理？
          - 有超时时间，超时后业务失败，释放连接
          - 延时等待时，可以并行处理其他请求，包括同一接口
    - 接口安全覆盖
      - 接口中是否涉及到认证和鉴权的测试覆盖？
        - 是否有认证和鉴权机制保护（不仅仅是IP白名单）？
        - 是否会有用户无法修改的口令？
        - 是否会有空密码或者简单密码（包括初始口令）的情况？
      - 是否有非查询的接口操作？
        - 非查询类的接口（增删改）被调用时须在后台记录日志
        - Web上用户非查询操作需在后台记录日志
      - 接口请求和响应中是否涉及敏感数据？
        - 敏感数据的传输通过HTTPS/VPN/SFTP方式加密，是否需要测试？
        - 涉及的敏感数据在数据库、文件、配置等介质中需加密后保存，是否需要测试
        - 相关的日志、告警、消息跟踪、调试信息中不能打印明文的敏感数据，是否需要测试？
        - 特性涉及个人/企业隐私数据界面展示时，须做匿名化处理，是否需要测试？
        - 典型敏感数据定义
          - license/证书
          - 口令/秘钥
          - 银行账号
          - 认证凭据
            - 短信验证码、动态口令、指纹等
          - 个人数据
            - 证件号码（Certificate number）
              - 身份证号、社保号、护照等
            - 信用卡账号\信用卡有效期\信用卡CVV
            - 充值卡号
            - 充值卡密码
            - 原始通信内容
              - 包括短信、彩信、邮件，系统(譬如类似10086）发送给个人的短信也算
            - 电话号码
            - 邮箱地址
            - 通讯地址
    - 接口兼容性覆盖
      - 该接口是否是对已有接口的修改？
        - 对接口进行新增操作？
          - 新增字段需要可选，兼容历史调用方式
          - 新增字段，字段可选时，不携带新增字段调用时，系统赋予的默认值是什么？
          - 字段新增的取值，是否保障了原取值含义不变？
        - 对接口进行修改操作？
          - 不允许修改URI、字段名称、格式、取值、含义
          - 不允许提升参数校验的严格程度
          - 接口中存在列表内容有顺序要求的，对于列表的修改，保持原顺序不变
        - 对接口进行删除操作？
          - 不允许删除字段、字段枚举值
      - 为了实现接口，是否会修改数据库对象结构？
        - 数据库对象结构新增操作？
          - 新增字段，应该有默认值
        - 数据库对象结构修改操作？
          - 不允许修改字段名称、格式、取值含义
        - 数据库对象结构删除操作？
          - 不允许删除字段、字段枚举值
    - ...
