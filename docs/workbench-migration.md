# 工作台迁移记录

来源：D:/GitHub/clouddoc-autotest，迁移日期 2026-11-17。

迁移 workbench 后台、网页模块、共享专家及通用设计模板。专家原有跨工程引用提取为本工程的只读方法片段；不再依赖源仓库路径。设计模板仅提供方法，不构成健康管理业务规则。

默认产品为健康管理；空白任务库；独立端口 8878、浏览器存储键和本地数据目录。未迁移原工程 .local、.auth、业务测试数据或历史任务。

## 使用链路

1. 首页创建任务，导入规格，确认资料。
2. 按需求分析 → 方案 → 用例依次生成、人工审阅并确认；未确认的业务问题保留待办。
3. 已确认用例可进行手工执行并形成报告，或纳入自动化资产。
4. 自动化执行页面刷新脚本目录，将脚本纳入资产并建立套件；填写测试环境配置后选择环境执行。
5. 查看执行结果、失败项、重跑和报告；知识库和任务资料由本地后台持久保存。

## 边界

真实 UI pytest 已接通，API 框架仍为独立命令入口。模型调用依赖已安装并登录的 CLI，未进行真实模型验收。脚本自动生成、产品认证、并行/暂停以及具体健康管理业务 E2E 尚未实现；不能把这些功能当作已完成。

工作台只绑定本机，不是多人共享服务。原工作台不会受到影响。升级前可从设置导出备份。

## 验证

`python -m unittest discover -s workbench -t . -q` 执行后台回归，其中健康执行器测试调用真实 pytest 和 Chromium，在临时目录运行合成页面并检查脚本漂移拒绝；不连接产品。`python scripts/run.py verify` 验证 API/UI 框架。前端已通过首页及六个导航页面浏览器检查。
